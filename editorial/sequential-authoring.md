# 3장부터 부록까지 순차 집필

2026-11-04 사용자 요청: 3장부터 끝까지 작성해 올리되 병렬 작업을 하지 않는다.

3장, 4장, 5장, 6장, 7장, 8장, 9장, 10장, 11장, 12장, 13장, 부록 A, 부록 B 순서로 수행한다. 한 장의 자료 대조·집필·검증·지면 검수·커밋·push를 끝낸 뒤 다음 장에 들어간다. 하위 에이전트를 사용하지 않으며 여러 장을 동시에 생성하지 않는다.

## 장별 공통 완료 조건

1. 목차의 강의 슬라이드와 해당 라운드 코드를 읽고 독자의 조사 질문을 정한다.
2. 전용 실행 이름으로 오프라인 자료를 생성하고 해시·기간·건수·필드를 검사한다.
3. 공동 SIEM의 기존 인덱스 상태를 시간 간격을 두고 확인한다. 소멸·UUID 변경·건수 감소가 있으면 서버 작업을 멈추고 기다린다. 기존 자료를 삭제하거나 복원해서 상태를 맞추지 않는다.
4. 새 전용 인덱스에만 적재한다. 쿼리 응답과 원문을 대조하고 실제 UI 화면을 확보한다. 합성 rule 필드와 실제 규칙 경보를 구분한다.
5. 본문·복사용 입력·조사표·실패 확인·원상복구를 연결한다. 강의의 과도한 단정과 필드·시간 해석을 바로잡는다.
6. 장별 DOCX를 B5로 렌더하고 모든 지면과 삽화 원본을 개별 검수한다. 내장 그림 해시와 전체 URL을 대조한다.
7. 검증한 범위와 남겨 둔 전용 자료를 기록하고 3권 원격 main에 push한다. 1·2권과 REV01은 보존한다.

12장은 공개 PCAP의 출처·이용 조건·해시를 확인한 뒤 파일 분석을 먼저 수행한다. 패킷 재생은 공유 실습망과 분리된 환경에서만 다루며 실제 시스템 공격을 실행하지 않는다. 원본 PCAP·악성코드·비공개 표본·인증 정보는 저장소에 넣지 않는다.
