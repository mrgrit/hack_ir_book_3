사용자의 순차 집필 요청에 따라 3장만 먼저 작성·검증했다. 대상은 「정찰과 분산 탐색」 B5 25쪽이다. Module03 30~62슬라이드, r02_recon.py, R02 Wazuh·Suricata·ModSecurity 규칙을 읽고 새 본문을 작성했다. 강의 저장소 추적 파일은 변경하지 않았다.

## 데이터와 실제 확인

- 기준 커밋 `d6a2397fc31517147ddd09f58e0d153bc8cf0588`, R02, seed 202, anchor 2026-11-01, 90일, scale 0.005, run-id ch03.
- 생성은 Windows의 오프라인 도구에서 수행했다. 전체 84,392건, background 82,716건, scenario 1,676건이며 시간 범위 밖 제거는 0건이다. 파일 검사를 거쳐 Ubuntu 호스트에서 새 인덱스 `book3-r02-ch03`에 적재했다.
- 세 차례 시간 간격을 둔 기존 인덱스 관측에서 소멸·UUID 변경·건수 감소가 없었다. 기존 인덱스와 공용 템플릿·규칙·서비스는 변경하지 않았다.
- 9개 쿼리를 실제 indexer에 실행했다. 응답은 `chapter03-query-results.json`에 저장했다. `verify_chapter03.py`는 모든 원본 합성 이벤트로 건수·고유 값·날짜·첫 원문 시각을 대조한다. 결과와 bulk 해시는 `chapter03-data-verification.json`에 있다.
- 웹 원문 34,636건, 방화벽 원문 986건이다. 221.49.17.120의 전체 웹 요청은 347건, 404 341건·고유 경로 241개·서비스 2개이다. 두 API는 444건·고유 출발지 300개·교집합 144개이다. 142.66.143.170의 방화벽 원문은 873건·포트 98개·목적지 8개·활동 날짜 55개이다.

## 설명 수정

강의의 244만 건 규모와 현재 84,392건 규모를 섞지 않았다. 요청량 1위·국가 정보·고유 경로 수만으로 정상/악성이나 사람/자동화를 단정하지 않고 승인 범위와 원문을 확인하도록 했다. data.url에 질의 문자열이 포함되는 점, 상위 후보 밖의 자료, 고유 지표 정렬에서 오차 상한 -1의 의미를 설명했다.

Wazuh 190203에는 same_url이 없으므로 “같은 경로” 설명과 실제 조건을 구분했다. 빈도와 different_dstport를 전체 기간의 고유 포트 집계로 바꾸어 해석하지 않았다. Suricata SYN 횟수와 고유 포트 수를 구분했고, ModSecurity 90201의 실제 차단 코드는 403임을 반영했다. 규칙 설치·실행·차단 효과를 시험했다고 주장하지 않았다.

## 지면과 자산

초안 26쪽 전체를 개별 검수한 뒤 준비 명령의 실행 순서와 규칙 설명을 다듬어 25쪽으로 조판했다. 최종 변경 지면을 다시 열어 확인했고 변경 없는 지면은 픽셀 동일성으로 이전 개별 검수와 연결했다. 마지막 수정은 화면 상단의 이전 줄 잔여 픽셀 제거이다. 최종 14·15·16쪽을 다시 확인했다.

검수된 기존 2권 `assets/illustrations/natural-angle/black-repeat-request.png`를 변경 없이 복사했다. 원본에서 두 팔·손의 연결, 엄지·손등, 의자와 골반·발, 노트북과 시선을 확인했다. 후드 상의의 검은 여우 패치와 자연스러운 뒷모습을 유지했다. 관계 도식 1개, 실제 UI 1개, 인물 삽화 1개를 내장했다. 이미지 해시·B5 판형·여백·테마·검정 본문·전체 URL 5개·복사용 쿼리 9개의 일치는 `chapter03-artifact-verification.json`에 기록했다.

검수 PDF는 build에만 있다. 실제 공격·패킷 재생·기존 인덱스 삭제·공유 환경 설정 변경은 수행하지 않았다. 선택 원상복구 DELETE도 실행하지 않았으며 실습 인덱스는 검토용으로 보존한다. 깨끗한 VM 설치부터의 재현, 실제 경보·규칙 평가와 git pull 전체 흐름은 이번 검증 범위에서 제외한다. 1·2권, REV01, 3권 1·2장 DOCX는 보존한다.
