# purple-agg 현실성 점검

기준일 2026-11-03. 기준 커밋 d6a2397fc31517147ddd09f58e0d153bc8cf0588. 강의 저장소는 수정하지 않았다.

## 결론

이미 구현된 장기 잠복과 활동 재개, 방문 편중, 정상 인증 오타, 배경 스캔, 허가된 점검과 백업은 유지할 가치가 있다. 그러나 현재 생성물을 ‘실제 간격 분포를 재현한 로그’로 표현하기에는 근거가 부족하다. 가장 먼저 집계 시간 단위와 관측 단위를 확정해야 한다. 다음으로 기간별 사건의 선후관계와 세션 모델을 정비하고, 실제 표본에 쓰인 집계기를 합성 데이터에도 같은 방식으로 적용하여 비교한다.

이번에는 확실히 재현한 정렬·파일 관리 문제를 교재용 도구에서 교정했다. 세션 간격을 임의로 60배 바꾸거나 평균·표준편차만으로 원시 패킷을 복원하지 않았다. 남은 현실성 개선은 아래 수용 기준을 따르는 후속 작업이다.

## 자료와 검증 범위

- 실제 집계 표본: 2019-05-26(일), 05-27(월), 05-30(목)의 XLSX 3개, 총 34,425행. 주말과 평일, 작은 파일과 큰 파일을 함께 보려는 목적 표본이며 무작위 추출이 아니다.
- 중복 출발지는 log_end가 최신인 행, 동률이면 날짜가 최신인 파일을 선택해 31,479개 출발지의 합집합을 얻었다. 날짜별 행 수를 당일 원시 이벤트 수로 보지 않는다.
- 각 파일의 SHA-256·열 목록·분위수·분모는 sample-statistics.json에 있다. 원본 IP·조직·도메인·개별 행은 저장소에 넣지 않았다.
- Counter.ipynb는 pickle 파일을 읽어 DataFrame을 표시하는 코드이다. 집계 특징의 계산 함수는 포함하지 않는다. 276MB PK 파일은 역직렬화하지 않았다.
- 기존 프로파일이 언급하는 2019-03-02 파일을 이번 접근에서 찾지 못했다. 기존 13,543개 출발지 통계를 원자료로 재산출했다고 주장하지 않는다.
- 동적 검사: 13개 라운드 × 기간 7·30·90·365일의 시나리오 생성, 4개 라운드의 90일 전체 스트림(scale 0.005). 서버·실제 공격·센서 재생은 실행하지 않았다.
- Windows에서 원본 모듈의 anchor=0 사전 계산이 음수 epoch 오류를 냈다. upstream.py는 모듈의 gmtime만 UTC datetime 연산으로 대체한다. 실제 학습 날짜·시나리오 로직은 유지한다. 이 호환 처리를 적용한 결과가 generator-probes.json이다.

## 현실성 개선의 다음 설계

1. **관측 사양 고정**: event_time·sensor_time·ingest_time, 시간대, 집계 창, 원시행/요약행의 단위를 선언한다.
2. **행위자와 세션**: 호스트·계정·세션·프로세스·트랜잭션 식별자를 유지한다. 정상·승인 행위와 공격 행위를 동일 시간대에 섞되 별도 정답 파일에서 분류한다.
3. **시간의 세 계층**: 활동 일수와 재방문, 하루 안의 세션 시작, 세션 안의 요청·응답·재시도를 분리한다. 업무 시간·공휴일·점검 일정은 환경 매개변수로 둔다.
4. **관측 왜곡**: clock skew·수집 지연·누락·중복은 사실 이벤트와 별개 계층에 적용하고 적용량을 manifest에 기록한다. 원본 사건 순서와 도착 순서 둘 다 보관한다.
5. **평가**: 동일 집계 함수로 일별 건수·활동 일수·시간대·목적지 수·간격 분포·짧은 창의 분산/평균·자기상관·누락률을 비교한다. 학습용 조정 표본과 검증용 날짜/출발지 집단을 분리하고, 오탐·미탐·탐지 지연을 승인 행위까지 포함해 평가한다.
6. **통과 조건**: 의미 불일치·음수 간격·선후관계 위반은 0건. 분포 허용 오차는 표본 변동의 범위로 정한다. 확인되지 않은 간격 단위에는 임의의 수치 통과선을 붙이지 않는다.

## R10 추가 점검 — 2026-11-04

R10 seed 1010/90일/배율 0.005의 85,969건과 실제 조회 9개를 대조했다. 상세 수치와 검증 범위는 chapter10-review.md에 있다.

- 안내문 added 30건은 고유 경로 3개에서 반복된다. 생성기는 i % 40과 연도 2020 + i % 6을 함께 사용하여 2020·2022·2024만 선택한다. 파일 상태를 유지하고 최초 added, 후속 modified 또는 삭제 후 added의 근거를 명시하도록 개선해야 한다. 수용 조건은 삭제/초기화 없는 동일 경로 반복 added를 설명 가능한 사건으로 한정하는 것이다.
- 장애 modifier는 일반 웹 세션에만 적용되고 가용성 모니터는 항상 200을 만든다. 축소 자료의 장애 예정 25분에는 점검 3건만 남아 모두 200이다. 업무 경로·점검 경로·백엔드 의존성과 장애 범위를 상태 모델로 분리하고, 각 경로가 영향을 받는 경우 일관된 응답을 만들도록 개선해야 한다. 배율별 관측 커버리지도 manifest에 기록해야 한다.
- scenario/background는 코드 출처이다. 장애와 첫 화면 크기 변경이 background에 적용되는 경우가 있어 악성/정상 라벨로 사용할 수 없다. 파일 상태·서비스 상태·행위 승인·관측 출처를 별도 정답 축으로 분리한다.

위 내용은 현재 코드와 출력에서 확인한 결함 및 개선 수용 기준이다. 강의 원본을 수정하거나 결함을 보정한 배포 버전을 실행했다고 주장하지 않는다.
