# 3권 집필 착수 계획

기준일: 2026-11-03. 가제: **로그 생성과 집계 기반 침해분석**.

2026-11-04 완료 기록: 아래는 착수 당시 계획이다. 이후 사용자 요청에 따라 1~13장과 부록 A·B의 초안을 완성했다. 3장부터 끝까지 순차 작업했으며 상세 진행은 sequential-authoring.md, 검증 범위는 verification.md를 따른다.

## 범위와 이번 착수 산출물

실제 시스템을 공격하지 않고 생성 로그 또는 공개 PCAP에서 얻은 관측 로그로 조사한다. 강의 슬라이드의 문장을 옮기지 않고 독자의 판단과 확인 행동을 중심으로 재구성한다.

이번 착수에서는 전체 목차와 자료 대응표, 생성기 현실성 점검, 식별자 없는 표본 통계, 오프라인 개선 도구, 1장 초안을 완성한다. PCAP 연계는 별도 설계와 재현 명령을 마련한다. 뒤 장은 자료 대응과 실습 성공 기준부터 정하고 순서대로 집필한다.

## 집필 순서

1. 강의 2개와 생성기 기준 커밋을 고정한다. 실습 13라운드의 역할과 생략된 번호를 명시한다.
2. 실제 XLSX의 행 단위, 중복 열, 집계 기간, 시간 정밀도, 간격 단위를 조사한다. 실측·추론·미확인을 구분한다.
3. 생성기에서 쓰는 통계와 쓰지 않는 통계, 시간 창 밖 이벤트, 재현성, 정상과 배경 스캔의 분류, 단계 간 인과관계를 검사한다.
4. 원본을 편집하지 않는 오프라인 개선 도구와 시험을 만든다. 개선 전후 차이와 아직 고치지 않은 항목을 기록한다.
5. 전체 교재 목차를 강의 슬라이드·라운드·독자의 산출물에 대응시킨다. 1장은 파일 생성과 구조 확인까지 완결한다.
6. PCAP 오프라인 분석을 기본으로 두고, 독립된 폐쇄망 재생을 선택 절차로 설계한다. 센서 로그와 호스트 로그의 관측 한계를 설명한다.
7. DOCX와 코드·예제를 검사하고 이 저장소에만 push한다.

## SIEM 공동 사용 계획

이번 착수 작업은 SIEM 연결 없이 수행한다. check, gen의 직접 적재, reset, monitor, kt66-setup.sh, 규칙 설치, 서비스 재시작은 실행하지 않는다. 특히 원본 gen은 같은 라운드 인덱스를 DELETE 후 재생성하므로 공동 작업 중 바로 실행하면 안 된다.

후속 실서버 검증은 다음 조건을 만족한 뒤 한다.

- 작업 전에 담당자·실행 시각·대상 인덱스·문서 수·UUID를 기록한다. 읽기 전용 상태 확인 중 변경이 있으면 적재 계획을 보류하고 기다린다.
- 일정 간격의 여러 관측에서 대상 상태가 유지되고 사용자 또는 작업 기록으로 사용 시간대를 확인한 뒤 진행한다. 우연히 잠깐 안정적이었다는 이유로 공용 자원 변경을 승인받은 것으로 취급하지 않는다.
- 전용 인덱스 이름 book3-<라운드>-<실행ID>를 사용한다. purple-*와 wazuh-alerts-*의 삭제·재생성을 피한다. 템플릿 범위도 전용 접두사로 한정한다.
- 센서 재생은 별도 출력 경로·규칙 ID·학습용 agent를 설계한 뒤 수행한다. 공용 manager의 전역 규칙·active response는 이번 작업에 적용하지 않는다.
- 예상치 못한 로그 소멸·UUID 변경·문서 수 감소가 나타나면 중단한다. 자동 재시도·자동 reset으로 덮어쓰지 않는다.

## 교재의 증거 경로

| 경로 | 생성되는 증거 | 확인 가능한 범위 |
|---|---|---|
| 생성기 → NDJSON → 전용 인덱스 | 학습용 이벤트와 사전 부여한 rule 필드 | 검색·집계·조사 논리 |
| 원문 로그 → Wazuh manager | 디코더 출력과 실제 규칙 경보 | 디코딩·상관 규칙 |
| PCAP → Suricata 또는 Zeek → 로그 → Wazuh | 패킷에서 센서가 관측한 이벤트 | 네트워크 탐지·연계 |

서로 다른 경로의 경보 수를 동일한 성공 기준으로 삼지 않는다. 합성 rule.id는 정답 보조값이고 실제 탐지 검증의 근거가 아니다.

## 통과 기준

- 통계: 원본 해시·표본 선택 근거·분모·결측·중복 열·누적 스냅샷 중복을 기록한다. 원시 간격을 알 수 없으면 복원했다고 쓰지 않는다.
- 생성: 같은 버전·seed·anchor·profile로 동일 파일, 시간 범위 준수, 시간순 정렬, 명시한 JSON 구조와 별도 정답 파일, 오류 시 기존 파일 보존.
- 시나리오: 인증 실패와 성공, 지속성 전후, C2·유출의 선후관계 및 정상 반례를 확인한다. 성능 배율이 정상/시나리오 비율에 주는 영향을 표시한다.
- PCAP: 출처·이용조건·SHA-256·패킷 수·기간·센서 버전·설정·규칙 해시·오류 수를 기록한다. 재생 시간 압축을 원래 탐지 시간 창과 혼동하지 않는다.
- 원고: 각 절에서 목적·도구 역할·실행 위치·입력·확인·실패 대응·원상복구를 연결한다. 실제 검증과 미실행 설계를 분리한다.
- 출판: 별도 B5 DOCX, 전체 URL, 실제 그림 삽입, 모든 지면 렌더 검수, 소스와 내장 이미지 해시 대조.
